# hiring-traps

공공기관 채용공고에서 사람이 읽어도 놓치는 줄을 뽑는다. Upstage Studio로 문서를 읽고, 판정은 코드가 다시 센다.

## 지금 상태

함정을 아직 세지 않았다. 공고문 스무 건을 모았고, Studio를 세 건에 태워봤다.

채용공고는 다섯 쪽이면 사람이 삼 분에 읽는다. 그래서 읽어주는 도구는 값이 없고, 값이 있는 자리는 읽고도 놓치는 몇 줄이다. 자격 기준일이 접수마감일인지 최종시험일인지, 우대인 줄 알았는데 필수인 항목, 가점이 중복되는지 택일인지, 서류 발급에 며칠 걸리는지.

넷 다 아직 가설이다.

## 세기 전에 다섯 번 틀렸다

함정을 한 건도 안 셌는데 측정 장치가 다섯 번 틀렸다. 함정 어휘를 머리로 만들어 서른여섯 쪽 공고문에서 넷이 0건이었고, 표본을 앞에서부터 받아 스무 건 중 열다섯이 병원이었고, 첨부의 첫 PDF를 집어 직무기술서가 표본에 들어왔고, 목록 한 쪽의 타임아웃 하나가 수집 전체를 죽였고, 「중복지원 불가」가 「가점 중복 배제」로 잡혔다.

마지막 것은 뜻이 정반대다.

전부 [docs/phase0-notes.md](docs/phase0-notes.md)에 그대로 적었다.

세기 전에 도메인 사실도 나왔다. 공고 서른세 건을 살펴 스무 건을 건졌고 열세 건은 건너뛰었다. 첨부가 아예 PDF가 아니거나(아홉 건) 붙은 PDF가 직무기술서였다(네 건). 공공기관 채용공고를 기계로 읽으려면 상당수는 애초에 읽을 물건이 아니다.

## Studio는 억지로 답하지 않았다

새 에이전트는 API로 못 만들고 Studio UI에서 가져오는 길밖에 없다. 그래서 먼저, 다른 프로젝트에서 쓰던 입찰 자격 에이전트에 채용공고를 그대로 넣어봤다.

세 건 모두 `OTHER_REVIEW_REQUIRED`를 확신도 0.99로 내놓고 분류 단계에서 멈췄다. 뒤 단계는 돌지 않았다.

도메인이 다른 문서를 아는 갈래로 우겨넣는 대신 사람에게 넘긴 것이다.

반대 경우를 생각하면 이게 왜 값이 있는지 보인다. 채용공고를 제안요청서로 잘못 분류했으면 추출 단계가 「입찰 참가자격」을 찾으러 돌았을 것이고, 그럴듯한 값이 나왔을 것이고, 틀렸다는 것을 아무도 몰랐을 것이다.

## 다음

채용공고용 에이전트 정의를 코드로 만들고 Studio에 올린다. 그 뒤에 함정을 센다.

지금 세면 사람이 읽은 수일 뿐이고, 이 저장소가 묻는 것은 기계가 그걸 잡느냐다.

설계는 [docs/superpowers/specs/2026-08-25-hiring-traps-design.md](docs/superpowers/specs/2026-08-25-hiring-traps-design.md)에 있다.

## 돌리는 데 필요한 것

파이썬 3, PyMuPDF, 그리고 Upstage API 키. 키는 `.env`에 `UPSTAGE_API_KEY=`로 넣는다. 받은 PDF는 저장소에 없다. `docs/phase0-manifest.json`에 기관명과 파일 번호와 sha256이 있어 같은 파일을 다시 받을 수 있다.

```bash
python probe/collect.py 20      # 표본 수집
python probe/locate.py          # 함정 후보 줄의 위치
python probe/studio_run.py fixtures/live/<번호>.pdf <agt_...>
```

윈도우에서 개발했고 맥과 리눅스는 확인하지 않았다.
